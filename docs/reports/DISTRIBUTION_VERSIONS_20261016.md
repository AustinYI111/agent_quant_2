# 历史分红重复版本处理（2026-10-16）

真实训练及样本外回测仍未完成。本轮修复原始采集阶段把同日重复记录一概视为请求失败的问题；不使用重复记录增加分红，不改变主事件库已确认的投资者权益。

## 原因与规则

九次原先失败的请求重新读取后，均返回同一除权日两条记录。八组为完全相同，或一条完整记录包含另一条的全部已知字段；一组包含不一致的现金分配条款。

采集阶段保存全部原始行，并统计重复执行日的行数。年份不符、非标准日期、证券代码和结构错误仍拒绝。原始文件不去重，后续重复处理依据文件 SHA256 和行号重放。

规范化只选择“逐字段包含该组所有已知值”的真实原始行。不把两个不完整版本拼成一条完整记录；一条原始记录缺金额时，也不会单靠文字补金额。候选行仍须通过原有金额／描述交叉校验、支付日期及公告可见日检查。

完全相同的多个候选行任选其等值最早行号作为代表，保留全部 source_rows_json。只要同一执行键存在不一致的非空字段，整组隔离，不按行序、最新时间或字段数量强行取值。duplicate_audit.csv 保存每组原始行、选中行及状态，rejected.csv 保存未通过行，两者均记录哈希。
