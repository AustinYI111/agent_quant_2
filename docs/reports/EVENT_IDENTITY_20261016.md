# 历史证券代码与分红连接（2026-10-16）

第一阶段仍在准备真实历史数据，尚未完成真实 LightGBM 训练和样本外收益。此次修复供应商把后来的证券代码回填旧历史时，分红与行情身份不能连接的问题。

## 实现与证据

正式实施公告确认中航电测 `300114` 在 2025-02-17 起改为 `302132`，投资者所持股数不因代码变更而改变。使用 2025-02-15 公布的正式实施公告，不以早期拟变更提示代替实施依据；来源 URL、SHA256 和页码保存在 `config/same_issuer_code_changes.json`。原始 PDF 及核对材料只在本地 `artifacts/official_avic_code_change_20261016`。

`reconcile-dividends --code-changes ...` 可先把独立支付记录映射到稳定发行人，再核对供应商事件。输出分别保留 `symbol`、`provider_symbol` 和 `payment_provider_symbol`；原始文件不改。审阅配置可以用旧公告代码及显式新供应商代码，但两者必须由验证过的同一发行人映射证明，不能猜测或忽略金额／股份／日期冲突。映射后重复事件拒绝，不自动去重。

302 是该正式创业板代码使用的前缀，现已被 A 股代码规则支持；进入真实股票池仍需证券身份和日期校验。原始行情按代码生效区间过滤失效别名，历史选股仍用当时的交易代码。2025 年映射证据用于重建供应商历史身份，不作为 2018—2024 年的预测因子，也不把重组新增股份视为老股东股票拆分。

对账封存完整代码映射和哈希。全市场数据准备会核对封存证据原字节，并要求特征侧提供同一策略；缺失、篡改或不同的映射拒绝。字符串／时间戳日期和整数／浮点股数比例采用一致的规范化序列化。模型及数据也使用此规范身份策略。
